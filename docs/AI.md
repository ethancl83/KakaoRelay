# AI 챗봇

Windows 앱의 **AI 챗봇** 탭에서 로컬 대화 읽기, 분석, 질문, 답변 생성과 자동 답장을 사용합니다.
Python은 필요하지 않습니다. C# 엔진이 SQLCipher 4 DB와 마지막 커밋까지의 WAL을 검증하고 메모리에서 조회합니다.

## 작은 창과 방별 페르소나

- 창은 490×760 고정 크기입니다. 상단 탭 오른쪽의 표시로 자동답장 가동 여부를 확인합니다.
- 탭 순서는 **자동답장 → 페르소나 → 프로바이더 → 대화분석**입니다.
- 자동답장 목록에서 방을 선택한 뒤 봇과 답변 방식을 고르고 **연결**을 누릅니다. 여러 방을 선택했다면 마지막으로 선택한 한 방에만 적용합니다. 그 방을 선택 해제하면 남은 방 중 마지막 선택 방을 사용합니다. 방 목록에 봇 이름과 답변 방식 **즉시 / 호출 / 맥락**을 칩으로 표시합니다. 미연결 방은 첫 번째 페르소나를 사용합니다.
- 호출어 답변 모드는 해당 방의 **@봇이름**만 사용합니다. 별도 호출어는 지정하지 않습니다. 이름·연결 변경은 다음 폴링부터 반영됩니다.
- 페르소나 3개를 봇 이름으로 구분하며 이름 옆 **이미지 첨부**로 자동답장 이미지 사용을 선택합니다. 같은 탭 안의 **이미지**에서 기준 이미지·감정별 후보를 생성하고 적용합니다.
- 자동답장은 폴링/카카오 ID/방 새로고침을 위쪽 한 줄에 두고, 넓어진 방 목록 아래에서 봇/답변 방식/연결을 한 줄로 설정합니다. 별도 채팅방 드롭다운과 설명 문구, 탭 전체 스크롤을 제거했습니다. 방이 많으면 목록 내부에서 스크롤합니다.
- 답변 방식은 방마다 따로 저장하며 **연결** 버튼으로 봇과 함께 적용합니다. 실행 중 변경은 다음 폴링부터 반영됩니다. 기존 설정에 방별 값이 없으면 이전 답변 방식을 유지합니다.
- 이미지 전송은 앱의 `WM_DROPFILES`와 HWND 전송 확인을 사용합니다. Computer Use·클립보드는 필요하지 않습니다. 실제 PNG 첨부 발송은 로컬 대화 기록으로 확인했습니다.

## 시작

1. 카카오톡과 원하는 방을 엽니다.
2. **AI 챗봇 → 방 새로고침**에서 방을 선택하고 **대화 읽기**로 문맥을 확인합니다.
3. **프로바이더**에서 CLI 실행 파일·모델·effort를 설정하고 저장합니다.
4. **페르소나**에서 봇 이름, 역할, 말투, 대화 성향, 추가 지침을 저장합니다.
5. **대화 분석**, **답변 만들기**, **질문하기**를 사용합니다. 답변 초안은 편집 후 **발송란으로 가져오기**로 옮깁니다. 가져오기만으로 전송하지 않습니다.

**JSON 저장**은 선택한 최근 문맥을 내보냅니다. Portable 버전에서 같은 파일을 가져올 수 있습니다.

## 프로바이더

- 기본 `auto`: **Codex → Grok → Claude**. 비활성화·미설치·실행 오류·시간 초과이면 다음 프로바이더를 시도하며 결과에 시도 내역을 표시합니다.
- 직접 선택은 시작 프로바이더입니다. 실패하면 Codex → Grok → Claude → Codex 순서로 순환하며 최대 2회전 후 종료합니다. 사용 안 함은 건너뛰고 직접 중지하면 즉시 취소합니다. 진행 상태에는 현재 회전과 프로바이더가 표시됩니다.
- 모델과 effort는 프로바이더별로 저장합니다. 모델을 비우고 effort를 `default`로 두면 CLI 기본값을 사용합니다.
- 모델/effort의 실제 지원 범위는 설치 버전과 계정에 따라 달라집니다. 잘못된 조합은 CLI 오류로 처리합니다.
- Codex CLI, **xAI Grok Build CLI**, **Claude Code**의 native 실행 파일을 사용합니다. Windows에서는 `.exe`, macOS/Linux에서는 실행 가능한 바이너리/런처 경로를 지정합니다. Windows `.cmd` 래퍼는 지원하지 않습니다.
- PATH 및 `~/.local/bin`, `~/.grok/bin`을 검색하며 Windows Codex 앱의 CLI 경로도 확인합니다.

설치와 로그인은 별개입니다. 해당 PC에서 `codex login`, `grok login`, `claude auth login`을 완료하세요. 비밀번호나 API 키를 페르소나에 넣지 마세요.

공식 참고: [Codex CLI](https://developers.openai.com/codex/cli/reference/), [Grok headless](https://docs.x.ai/build/cli/headless-scripting), [Grok 설치](https://docs.x.ai/build/overview), [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Claude 설치](https://code.claude.com/docs/en/setup).

## 자동 답장

**AI 챗봇 → 자동 답장**에서 폴링 간격(1~300초, 기본 5초)과 답변 방식을 선택합니다. 변경 내용은 자동 저장되며 가동 중에는 중지 후 설정을 바꿉니다.

- **즉시 답변**: 다음 폴링에서 발견한 새 텍스트 메시지마다 답변합니다.
- **호출어에만 답변**: 호출어로 시작하는 새 메시지에만 답변합니다. 기본 모드입니다.
- **대화 맥락상 판단 후 답변**: 각 새 메시지 시점의 최근 20개 메시지를 보고 봇이 답할 상황인지 판단합니다. 처음에는 `gpt-6-luna low`와 `grok-4.7 low`를 동시에 실행하고 먼저 유효한 판단을 낸 모델을 선택합니다. 같은 앱 실행 중 후속 판단은 선택한 모델을 사용하고, 실패 시 재비교합니다. 비활성 프로바이더는 제외합니다. 판단 실패·형식 오류는 발송으로 이어지지 않습니다.

내 ID, 호출어, 선택 방, 폴링 간격, 답변 방식도 설정 파일에 저장됩니다. 편집 후 약 0.7초에 자동 저장하고 직전 파일은 `.bak`으로 보존합니다. 실행 파일은 `artifacts/app`에 배포하며 설정 파일은 배포 폴더 밖에 유지합니다.

Windows에서 최대 3개 방을 감시합니다. **자동 답장** 탭에서 방 새로고침 후 1~3개 방을 클릭해 선택합니다. **내 사용자 ID**와 **호출어**(기본 `@그쫀쿠`, 호출어 모드에서 필요)를 입력하고 **선택한 방 자동 답장 시작**을 눌러야 켜집니다. 하단에 가동 중인 방 수, 각 방의 상태·경과 시간이 표시됩니다. 수동 분석은 별도로 사용할 수 있습니다.

- 시작할 때 기존 메시지를 기준점으로 잡고, 이후 상대방의 새 텍스트를 선택한 답변 방식에 따라 처리합니다.
- 답변할 메시지로 결정되면 바로 AI 답변을 생성합니다. 생성 중 상태는 앱에서 표시하고, 채팅방에는 준비 안내를 보내지 않습니다. 같은 방에서 이전 답변을 처리하는 동안 들어온 호출은 다음 확인 주기에 감지됩니다.
- 내 ID의 메시지·삭제 표시·비텍스트·과거 기록을 제외합니다. 한 번 확인한 호출은 반복 생성하지 않습니다.
- 같은 이름의 로컬 방이 여럿이면 시작하지 않습니다. 실제 전송 시에도 열린 창을 하나로 확인해야 합니다.
- 같은 방에서 여러 호출이 들어오면 메시지 순서대로 모두 처리합니다. 서로 다른 방은 별도 CLI 프로세스로 동시에 생성하며, 카카오톡 전송 단계는 직렬 처리합니다. 새 메시지가 최근 500개 조회 범위를 넘어 누락될 우려가 있으면 해당 방을 중지하고 표시합니다.
- 기존 발송 엔진의 초안 보호와 요청 ID 중복 방지를 사용합니다. 전송 결과가 불확실하면 중지하며 새 ID로 자동 재전송하지 않습니다.
- 트레이에서도 동작합니다. **중지**는 생성 프로세스도 취소하지만 이미 시작된 네이티브 발송은 결과 기록까지 마칩니다. 앱을 재시작하면 자동 답장은 꺼집니다.

## 저장과 전달

프롬프트, 설정 파일, 이미지 목록, 발송 이력, 진단 보고서, 대화 내보내기 및 HTTP JSON 응답은 한글을 `\uXXXX`로 치환하지 않고 UTF-8 원문으로 씁니다. 메시지 구분과 따옴표·줄바꿈 처리는 JSON 규칙을 유지합니다. 기존 방별 세션 식별자와 발송 중복 방지 해시는 유지합니다.

자동 답장은 답변 생성 → 답변 감정의 이미지 → 답변 텍스트 순서로 보냅니다. 페르소나의 이미지 첨부가 켜져 있으면 답변에 감정(기쁨·슬픔·놀람·화남·생각·응원)이 분명히 드러날 때 해당 감정의 채택된 이미지만 보냅니다. 해당 감정 이미지가 없으면 텍스트만 보냅니다. 특별한 감정 표현이 없는 neutral 답변은 그 방에서 오늘 첫 답장일 때만 기본 이미지를 보냅니다. 첫 답장이 감정 이미지 또는 텍스트만으로 나갔다면 이후 neutral 답변에는 기본 이미지를 붙이지 않습니다. 날짜는 컴퓨터의 현지 날짜이며, 방·계정별 첫 발송 기록은 로컬에 저장해 앱 재시작 후에도 유지합니다. 이미지 또는 텍스트 발송이 확인되기 전에는 첫 답장으로 기록하지 않습니다. 이미지 발송 결과가 불확실하면 뒤의 텍스트를 보내지 않고 중지합니다.

이미지 목록에서 후보를 선택한 뒤 **마젠타 투명화**를 펼치고 슬라이더 오른쪽 **적용**을 누르면 생성과 별개로 로컬에서 투명화합니다. 색상 허용 오차는 기본 30이며, 0은 정확한 `#FF00FF`만 제거합니다. 원본과 적용 상태를 유지한 새 PNG 후보로 저장하며, 캐릭터 내부의 마젠타도 투명화됩니다. 결과를 사용하려면 선택 이미지 채택을 누르세요.

이미지 생성에 전달한 프롬프트는 이미지별로 `library.json`에 함께 저장됩니다. 후보를 선택하고 **생성 프롬프트**를 펼치면 저장된 내용을 확인·복사할 수 있습니다. 투명화 후보도 원본 프롬프트를 유지합니다. 과거 기록에 프롬프트가 없으면 저장된 프롬프트 없음으로 표시합니다.

기준 이미지의 투명화본은 원본과 같은 캐릭터로 연결됩니다. 원본과 투명화본 사이에서 기준을 바꿔도 채택한 감정 이미지를 유지하며, 어느 쪽에서 만든 감정 후보든 채택할 수 있습니다. 새로 생성한 기준 이미지는 별도 캐릭터로 구분합니다. 이전 버전에서 만든 투명화 기준은 이미지 목록을 열 때 실제 픽셀 변환이 일치하는 원본이 하나일 경우 연결을 복구하고, 복구 전 목록은 `library.json.before-family-repair.bak`에 보관합니다.

이미지 생성은 **페르소나 → 이미지**에서 로그인된 CLI를 사용합니다. GPT는 Codex CLI의 `imagegen` 내장 도구, Grok은 Grok CLI의 `image_gen`/`image_edit` 도구로 생성·편집합니다. 앱은 이미지 API를 직접 호출하지 않고 API 키 입력도 받지 않습니다. 실행 파일 경로는 프로바이더 설정을 따릅니다. 기준 이미지는 감정 이미지 편집에 전달하고 결과를 PNG로 보관합니다. 도구 실패 시 API로 대체하지 않으며 기존 이미지와 선택은 유지합니다.

설정은 `%LOCALAPPDATA%/KakaoRelay/ai-settings.json`에 저장됩니다. 다른 OS에서는 .NET의 사용자 LocalApplicationData 경로를 사용합니다. 앱은 대화 키·복호화 DB·일반 분석 결과를 파일로 저장하지 않습니다. 사용자가 JSON 저장을 선택한 경우에만 대화 문맥을 내보냅니다.

생성을 누르거나 자동 답장을 시작하면 선택한 문맥과 페르소나가 해당 CLI의 AI 서비스로 전달됩니다. 실패 시 다음 프로바이더로 전환하므로 실패한 프로바이더에도 요청이 전달됐을 수 있습니다.

방·프로바이더·모델/effort·페르소나별 세션을 분리합니다. 다음 호출은 명시적인 세션 ID로 resume하고 추가·변경된 메시지만 전달합니다. 앱 재시작 후에도 `앱폴더/data/providers/<프로바이더>/conversations`의 세션 ID·메시지 해시를 재사용합니다. 대화 내용은 각 CLI의 세션 기록에 보관되며 자체 보관 정책을 따릅니다. 설정이 바뀌면 별도 세션을 사용하고, 취소·실패한 세션은 다음 요청에서 새로 시작합니다. 재개가 과거 문맥 처리 비용 자체를 없애지는 않습니다.

Codex 대화는 `app-server --stdio`, Claude 대화는 `--input-format stream-json --output-format stream-json`으로 방별 프로세스를 유지합니다. 같은 방의 후속 호출은 살아 있는 연결에 추가하고, 앱 재시작 후에는 저장된 ID로 복원합니다. 중지·시간 초과·통신 실패는 해당 연결만 폐기합니다. 실패 시 서비스가 다음 프로바이더로 전환하며, 2회전째 같은 프로바이더를 다시 시도하면 실패한 세션을 재사용하지 않고 전체 문맥으로 새 세션을 시작합니다. 직접 중지는 재시도하지 않습니다. 앱 종료 시 상주 프로세스도 종료합니다. 10분 이상 사용하지 않은 연결은 다음 요청 때 정리됩니다. 모델과 effort는 기존 프로바이더 설정을 그대로 사용합니다. Claude는 CLI 로그인이 필요합니다.

Grok 1.0.41의 `grok agent stdio` ACP에서도 연속 입력과 `session/load` 복원을 실제 확인했습니다. ACP는 CLI의 effort 인자 대신 `session/set_config_option`으로 `reasoning_effort`를 명시해야 했습니다. 이번 변경에서는 Grok의 기존 요청별 실행·resume 경로를 유지하고 상주 기능의 지원 여부만 검증했습니다.

프롬프트는 셸 명령으로 조립하지 않습니다. Codex/Claude에는 stdin, Grok에는 요청별 임시 파일로 전달하며 임시 파일은 종료 후 지웁니다. 작업 폴더는 방별 세션 폴더로 분리합니다. 취소/제한 시간 도달 시 자식 프로세스까지 종료합니다. 대화는 인용 데이터로 표시하고 삭제 본문은 새 분석 입력에서 제외합니다. 이미 CLI에 전달한 과거 내용은 세션 이력에 남을 수 있습니다.

## 웹검색과 대화 중 이미지 생성

Codex는 `web_search="live"`, Grok은 `web_search,web_fetch`, Claude는 `WebSearch,WebFetch`를 허용합니다. 최신 정보나 검색 요청에는 검색을 사용하고 답변에 출처 URL을 넣도록 안내합니다. 셸 실행이나 개인 MCP 연결은 추가하지 않습니다. Codex 설정은 [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)의 웹검색 항목을 따릅니다.

Windows 챗봇에서 현재 답변 대상이 새 그림을 요청하면 시각적 설명을 별도 CLI 이미지 생성기로 전달합니다. 답변 프로바이더가 Grok이면 Grok → Codex, Codex/Claude이면 Codex → Grok 순서로 사용 가능한 프로바이더를 최대 두 바퀴 시도합니다. 이미지 모델은 페르소나 이미지 관리의 기존 GPT/Grok 모델 설정을 사용합니다. Claude도 이미지 생성 자체는 Codex/Grok CLI에 맡깁니다. API 키나 직접 이미지 API는 사용하지 않습니다.

생성 결과는 경로·파일 시각·크기·이미지 디코딩 검증 후 `앱폴더/data/providers/<프로바이더>/generated-replies`에 PNG로 보관합니다. 자동답장은 생성 이미지 → 답변 텍스트 순서로 공용 발송 대기열을 사용합니다. 명시적인 그림 요청은 감정 이미지 첨부 설정이나 오늘 첫 답장 여부와 관계없이 전송하며, 그 답변에는 감정 이미지를 추가로 붙이지 않습니다. 생성에 실패하면 실패 안내를 보내고, 이미지 발송 결과가 불확실하면 텍스트를 보내지 않고 중지합니다.

대화분석/수동 질문의 생성 결과는 자동 발송되지 않습니다. `POST /v1/ai/generate`의 `reply`/`chat` 결과에 생성된 `imagePath`가 있으면 `POST /v1/send-image`로 먼저 보내고 텍스트를 보냅니다. `imageError`는 생성 실패의 진단 정보입니다. Portable은 웹검색을 지원하며, 새 이미지 생성·카카오톡 발송 연결은 Windows 앱에서 제공합니다.

## 플랫폼 범위

Windows 로컬 읽기는 현재 키 문자열이 카카오톡 프로세스에 로드된 SQLCipher 4 파일을 지원합니다. 닫힌 방·예전 프로필·구형 암호화 형식 전체의 복구를 보장하지 않습니다. 키를 찾지 못하면 방을 연 뒤 새로고침하세요. 한 요청은 최근 1~500개 메시지이며 프롬프트는 최신 내용 위주로 약 6만 글자, 개별 본문은 8천 글자까지 포함합니다. 일부 문맥 생략 및 첨부 미디어 미분석을 고려하세요.

macOS/Linux는 [Portable](PORTABLE.md) 앱에서 가져온 대화를 분석합니다. 카카오톡 DB 직접 읽기·직접 전송·자동 답장은 Windows 어댑터 기능입니다.

## 프로바이더별 저장소

모든 CLI 작업은 실행 파일이 있는 폴더의 `data/providers/codex`, `data/providers/grok`, `data/providers/claude`를 사용합니다. 답변·맥락 판단·이미지 생성에 동일하게 적용되며, 설정·로그인 파일·로그·네이티브 세션과 방별 재개 메타데이터가 개인 CLI 저장소와 분리됩니다. 각 CLI의 실행 파일은 기존 설치 경로를 사용합니다.

처음 실행할 때 기존 파일 기반 로그인 정보만 복사합니다. 개인 MCP·플러그인·후크와 임의의 외부 저장 경로 설정은 가져오지 않습니다. 기존 KakaoRelay 방의 세션은 해당 방을 처음 사용할 때 그 방에 기록된 세션 ID로만 찾아 복사합니다. 가져올 네이티브 기록이 없으면 전체 최근 문맥으로 새 세션을 시작합니다. 원본 기록은 유지하며 개인 Codex 앱의 과거 목록을 자동 삭제하지 않습니다. 키체인에만 로그인 정보가 있는 환경이나 로그인하지 않은 CLI는 전용 저장소에서 별도로 로그인해야 합니다.

배포 시 `data` 폴더를 보존해야 합니다. 폴더에는 로그인 정보와 대화 기록이 있으므로 배포 패키지나 Git에 포함하지 않습니다. 새 컴퓨터에는 실행 파일을 배포하고 해당 컴퓨터에서 로그인합니다. macOS/Linux에서도 실행 파일 옆의 쓰기 가능한 `data` 경로를 사용합니다.

공식 경로 설정: [Codex CODEX_HOME](https://learn.chatgpt.com/docs/config-file/environment-variables), [Grok GROK_HOME](https://docs.x.ai/build/settings), [Claude CLAUDE_CONFIG_DIR](https://code.claude.com/docs/en/env-vars).
